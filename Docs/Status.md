Quest embedded collection: `CyInsights.QuestGpuMetrics=1` enables available `XR_META_performance_metrics` readings during an active trace with its `counters` channel. The default observation mode is now once per game frame (`quest_hz=0`), with positive rates retained as an optional throttle; `CyInsights.Start` includes the channel on Android even if the capture channel list is overridden. Collection needs no external monitoring application and restores initially disabled runtime metrics after the plugin stops its capture. Every metric carries native units and validity; invalid/nonfinite readings do not become zero GPU times. The runtime does not expose an execution-frame ID or original measurement interval, so observation game frames and CPU cycles are explicitly separate from GPU execution. The provider follows Unreal's OpenXR extension hooks; a different XR backend requires its own adapter.

# Internal optional Windows collector — 11 October 2026

The single CyInsights plugin now contains `CyInsightsGpuLoader` and
`CyInsightsGpuWindows`. They reuse the owned collector code and build
`CyInsightsGpu.addon64`; the CyGPUInspector plugin and application are not used.
Loading is disabled by default, keeping native `.utrace` GPU capture as the basic
mode. Windows Editor/Runtime compilation passes on UE 5.5 and 5.8, and Android
ARM64 UE 5.5 excludes the extra Windows modules. A rendered UE 5.8 test recorded
345 commands (235 draws, 33 dispatches), GPU execution-frame timestamps and zero
resource readbacks through the internal backend. The combined archive opens in
CyInsights with both native timing and GPU command detail. See
[WindowsGpuCollector.md](WindowsGpuCollector.md). Detailed network payload transfer
is still unavailable; the optional recorder uses local IPC.
